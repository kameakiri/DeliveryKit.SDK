# FAQ

## Q. DeliveryKit.ApiTemplate は公開されていますか？
A. はい。このSDKの兄弟プロジェクトとして別リポジトリ（DeliveryKit.ApiTemplate）で
   公開しています。JWT認証・`[Authorize]`・入力検証を最初から組み込んだ、
   このSDKを使ったWeb APIの組み方一式のサンプルです。
   弊社の配送システム本体（プラン別機能・複数キャリア連携・DB永続化・
   IDOR対策を含むデータモデル等）は含みません。

## Q. ログは削除されますか？
A. **既定では削除されません。** 180日後に `LogsArchive` へ移動されるだけで、
   移動した先を片付ける仕組みは動きません。

   **これは容量より保存期間の問題です。**「隔離済み」は「削除済み」ではないので、
   このSDKで作った製品の事業者が利用者へ保存期間を示していても、ログに含まれる
   個人データはその期間を越えて残り続けます。しかも運用者からは毎日アーカイバが
   正常終了して見えるため、約束どおり消えていると思い込んだまま運用できてしまいます。

   `DeliveryKit.LogArchiver` の第4引数（または環境変数 `DELIVERYKIT_LOG_PURGE_DAYS`）で
   削除までの日数を指定すると、隔離先から削除します。**保存期間を決めるのは配布先の
   責任です。** 詳細は `docs/archiver.md`。

## Q. アーカイバを動かしていればログは片付きますか？
A. **実行された分しか働きません。** 単発の実行ファイルなので、Windowsタスク
   スケジューラなどで定期実行する前提です。Linuxコンテナや Azure App Service（Linux）の
   ように前提にできない環境では、**誰も起動しないままログが無期限に溜まります。**
   そうした環境ではホスト側のcron相当を用意するか、アプリのプロセス内で定期実行する
   常駐処理として組み込んでください（DeliveryKit 本体は後者を採っています）。

## Q. SDK のモデルを API 側で再定義する必要はありますか？
A. ありません。API は SDK のモデルをそのまま利用します。

## Q. AI パイプラインは必須ですか？
A. 任意です。そして**名前の割にしていることは少なく**、`Normalize()` は
   空行の除去と前後の空白の `Trim` だけを行います。

   **マスキングは一切行いません。** ログには氏名・住所・IPアドレス等が入るため、
   外部のAIサービスへ渡す場合は、渡してよい情報かの判断とマスキングを自分で
   実装する必要があります。`docs/ai.md` を読んでから使ってください。
